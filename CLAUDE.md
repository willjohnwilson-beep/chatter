# Chatter

Python/Flask harness for roleplay chat with several AI characters, built to test how character memory forms and is retrieved. A director model picks who speaks; characters only know what they were present for. The web UI is both the game and the author's tool. See `docs/HANDOVER.md` for a dated snapshot of design and status (it may be stale; trust the code and tests). **Only update the handover at the point of handover**, when the user asks for one: it is a document to pass information to the next session, not a living log, so don't refresh it as features land.

## Run

- `python app.py` serves on port 5005. In the Claude desktop app use `preview_start` with name `chatter`.
- Python changes need a server restart; templates auto-reload.
- Dependencies live in the project, in `vendor/` (git-ignored), and `app.py`, `llm.py` and the tests put it on `sys.path` at startup (the same effect as setting `PYTHONPATH`), so no launch flags are needed. **Never `pip install` into system Python.** Installing a new library into the project is fine and expected: add it to `requirements.txt` and run `python -m pip install --target vendor -r requirements.txt`. A new entry point or script must add `vendor/` to `sys.path` the same way (or set `PYTHONPATH=vendor`).
- API keys (`ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`) are in `.claude/settings.local.json` under `env` (git-ignored). Never print or commit them.
- Set `PYTHONIOENCODING=utf-8` when running scripts that print model output on Windows.

## Tests

- `python tests/test_engine.py`: deterministic suite, no network, ends with `ALL DETERMINISTIC TESTS PASSED`. One long script (not pytest) of numbered `print("== N. ...")` sections; append new sections before the final pass line. It rebinds `app.store/world/chat_engine` to temp objects, so it never touches live data.
- `python tests/test_llm.py`: OpenRouter translation layer against a fake transport.
- The `Fake` client in `test_engine.py` routes on distinctive phrases in prompts ("You direct a roleplay scene", "fact that was hidden at this place", etc.). **If you reword a prompt, update `Fake.create`.**
- `tests/experiments/` holds live-model A/B scripts (need keys; most take `M=<model id>`). `demo_driver.py` resets the live app through the API and replays the demo scenes; it needs the server running.

## Layout

`app.py` routes and global state; `chatter.py` turn pipeline; `state.py` world state and the watcher; `memory.py` retrieval, formation, consolidation; `vectors.py` embedding shortlist for very large memory stores; `director.py` speaker choice; `llm.py` provider routing (a model id with a slash goes via OpenRouter, a bare id goes direct to Anthropic); `library.py` saved scenarios (`scenarios/`) and sessions (`sessions/`); `scenario.py` the AI scenario drafter; `schedule.py` events on the story's clock.

Authored memories: a place's description and each seeded fact (`world.seeds`, the Knowledge editor) are kept in the memory store as memories with `origin` `place` or `seed`, synced by `Chatter.sync_knowledge` (so only whoever knows them holds them). Play never edits, merges or deletes them (`memory.AUTHORED`), and the narrator, omniscient about what happened, is not given one unless the author lists it or it is for everyone. `CHATTER_AUTHORED_MEMORIES=0` turns the sync off (the older test sections run with it off).

Place facts: the memory pass marks a world entry `observed` when a character reliably states what a place is like right now from their own looking (everything else stays a claim held by those who heard it). An observed fact, said aloud (`public`), is told, plainly and dated, to anyone at that place, including the offstage simulation (`MemoryStore.place_reports`, `Chatter._ledger_text`). A fact that cannot be true alongside a claim marks the claim "since contradicted"; two facts that disagree are flagged for the author; the author can demote a fact. The judge reads only the lines, so it cannot detect a lie; that stays author-side (`cross_lines`).

Stances: when the memory pass judges that a character's statement about themselves is a plan, opinion, rule or position they took (not history or who they are), it is recorded with source `stance`: worded as what they said, never core, short-lived, and shown to them apart from what is established about them ("you may change your mind") and to others as "said by X, a position they may change". Without this, a passing remark became an always-true trait with a "stay consistent" instruction.

Recall: the prefetch asks the retrieval model to rate each pick (3 the reply would be wrong without it, 2 better informed, 1 loosely related) and uses only 3s (`RECALL_MIN`), then adds up to two memories that share a distinctive word with the line (`memory.lexical_picks`, no model call) because the model sometimes misses a memory the line plainly names. On the Sixty session (`tests/experiments/exp_recall.py`): the right memory came back 78% of the time before, 89% now, with 2.9 memories per probe instead of 3.8 and 2.5 per line of small talk instead of 4.9. The scores alone (without the lexical picks) cost recall (65%), and telling the model to "return nothing for small talk" cost more. Switches: `CHATTER_RECALL_SCORED`, `CHATTER_RECALL_MIN`, `CHATTER_RECALL_LEXICAL`.

Scene moves: the scene is where the player is, and a character's call to move ("kitchen first... Come on, all of us") is an invitation, not a move. The player's own line moves the scene: `Chatter._premove` (before anyone answers; also asked when the others' last lines named a place, so "lead on" accepts an invitation) or, as the fallback, the watcher, whose proposed move is checked against the player's line alone (`WorldState._player_goes`; no player line, as when the story jumps, needs no check; a failed check is no move). Only characters who say or show they go come along (`companions` in the premove; location updates to the new place from the watcher): everyone else stays where they were, and a veto also cancels the companions it listed. Before this, an NPC's invitation moved the whole scene, player and all eight women, in 3 of 8 watcher runs. Now (DeepSeek, `tests/experiments/exp_scene_move.py` and `exp_scene_turn.py`): the invitation alone moved nothing in 16 of 16 watcher runs and 8 of 8 whole turns; two NPCs ordering everyone while the player asked about something else moved it 0 of 16 (4 of 16 without the check); a declined invitation 0 of 16; "lead on" moved it 16 of 16 with only the person who led (the prompt's example sentence did that; without it 2 of 8 runs took everyone). The watcher fallback still takes everyone in about 2 of 15 follow runs. A player line that only says what they will do ("I guess I'll go look at the hatch") is an announcement, so the others answer first: the premove returns `announce` and holds the move, and after the replies the watcher (or `Chatter._companions`, a small call asking who said they come) moves the scene with those who volunteered; what the premove sees before the line is what people SAID, never a stage direction (a narrator's "(X leaves for The Front Hall.)" once sent the player there). Measured on a fixed history (`tests/experiments/exp_scene_turn.py`, fixture `fixtures/scene_move_history.json`, 16 runs): announce ended in the kitchen after the replies 16 of 16 (0 moved before anyone answered; 2 of 8 did before the wording was tightened), "lead on" 16 of 16 by premove (one run took all eight), "*I walk over to the kitchen*" 16 of 16 before anyone answered.

Departures take two beats: a character who says they are going somewhere (`Chatter._announced_moves`), or whom the watcher sends there on a public turn (`watch(defer_leavers=True)`), only starts leaving (`leaving` on the character, a place id); they stay through the next exchange, are told so ("you leave when this exchange is over, so answer what you were asked"), and leave at the end of that turn with the usual "X leaves for Y" line unless the same model call that checks for announcements says they changed their mind or were asked to stay (`stays`). Before this, a character who asked the player a question while announcing a departure ("Anyone want to come and watch me do it?") was gone before anyone could answer; in one session four women left in a single turn. Whispers and "none" (gone for good) still move at once, and a move of the scene clears every pending departure. Live (DeepSeek, `tests/experiments/exp_depart_beats.py`, 12 runs of two turns): nobody left the room in turn 1 in any run (0 of 12; before the watcher change 2 of 8 runs had two people leave), and those on their way left at the end of turn 2.

Offers to go together: "Come on, I'll walk you round" or "Want me to come and have a look?" is an offer, so it waits for the player's answer and is not the speaker's own departure (rule in `_announced_moves`, with "if it still won't start, knock and I'll come" as a second example), and a line that follows one is asked about by the premove even though the player's "yes please" names no place (`INVITE_RE`; the prompt tells it to take the destination from what the offer plainly points to). Found on Marlbeck: Tom (the joiner next door) offered to walk Sam round to number 9 and the offer was registered as his own departure (in 10 of 12, 9 of 11 and 7 of 10 runs across the three replies); then "Yes please" took the scene to number 9 with him in only 3 of 12 runs and left Sam standing alone in Tom's yard, abandoned, in 5 of 12; a decline or an unrelated question still had Tom leave alone in 6 of 10 and 6 of 11 runs; "Want me to come and look?" plus "yes" moved nothing in 12 of 12 (`tests/experiments/exp_offer_go.py`, DeepSeek, N=12 per case). After: "yes" to the walk offer took the scene to number 9 with Tom in 10 of 10 (two failed calls left out), "yes" to the question 12 of 12, nobody left alone; the original three-turn replay (the player asks about the workshop instead) had Tom start to leave in 3 of 10 runs and in 0 of 10 after. Still wrong: an unrelated question moved the scene with Tom in 3 of 12 runs (the workshop question; 0 of 35 for three other non-accepting lines), the offer was still registered as a departure in about 1 of 10 runs, and a player's "I'll give it a go myself first" sent the scene to number 9 without Tom in 4 of 12 (arguably right). My first guess, that the conditional "knock on and I'll come and look" alone starts a departure, was not borne out: 0 of 12 through `_announced_moves` and 0 of 12 through the watcher (`exp_conditional_depart.py`, with `PATH_=watch` for the watcher). Sixty regression at N=8 (`exp_scene_turn.py`): invitation alone 0, "lead on" 8 of 8 with one companion, declined 0, unrelated 0, announce 8 of 8 after the replies, "I walk over" 8 of 8 before anyone answered. A few percent of the departure checks on DeepSeek failed with invalid JSON (caught and logged, so that turn's departure check is lost); not investigated. `exp_scene_turn.py` now builds its world from `scenarios/sixty.json` (it copied the live `world.json`, which had become Marlbeck); `exp_depart_beats.py` still replays the live session, so its numbers are not comparable now.

The word gate: `Chatter._announced_moves` asks a model about spoken departures only when a line passes `going_gate` (one call per turn however many lines pass). It used to need a going phrase (`GOING_RE`) AND a shared word of four letters or more with some place's name, brief or description, which let through only the plain ones: of 30 departures I wrote it let through 13, of 240 a model wrote in each character's voice without seeing the gate (`tests/experiments/gen_departure_lines.py`, fixture `fixtures/departure_lines.json`) 117 (49%); "nipping to the square" (the 'the' and the verb form), "popping over to the pub" ('pub' is three letters), "off to church" (church is not churchyard), "come round yours" and "heading upstairs" never reached the model, so those characters said they were going and stayed. Now there is a second way in, a first-person line (or a clause that opens with the verb, "Popping to the shop") with a verb of motion followed by a direction (`_MOTION_RE`: 'going out', 'nip to the', 'heading home', 'come round'; a bare "go" does not count, so "I'll go and have a think" still makes no call); the first way takes leaving phrases too (`_LEAVE_RE`: 'I'd best be getting along', 'time I made tracks', 'I'll be at the pub', 'if anyone wants me'), three-letter words of a place's name and brief, and the first five letters of a longer one (`shares_a_place_word`). The departure prompt also says never to guess a destination: 'home', 'my bed' or 'the shop' that no listed place is, or the nearest-looking place, is no move (before that rule "heading home" sent the speaker to the player's house, 7 of 177 runs). Measured (`tests/experiments/exp_gate.py`; `GATE=old` is the earlier gate; DeepSeek): the gate lets through 30 of 30 of my lines (was 13) and 171 of 240 model-written ones (was 117; most of the rest give no destination at all: "That's me done, see you later"), and passes 41% of real Sixty lines against 37% (20 of 49 against 18; so the old gate was never a strong saving). Through the model, 240 model-written lines at 2 runs each: registered for the right place 252 (was 197 of about 476), for another place 10 (7), failed calls 10 (4, invalid JSON caught and logged); my 30 departures and 18 'sounds like going' traps at 6 runs each: right place 118 of 178 (was 77 of 180), not registered 50 (103), wrong place 10 (0; 8 of them the Upstairs Landing for "my room" and "going to bed", where I had labelled a particular bedroom), traps that started a departure 0 of 107 (1 of 107 in the run before the prompt rule was refined: "I'll see you at the pub later", a plan). "I'm just nipping to the square for a coffee" went from never reaching the model to 11 of 11. Not fixed: a line with no place in it that depends on earlier talk ("I'll get my toolbag and come round", 0 of 11), which the check cannot resolve because it sees only this exchange. Regression at N=8 and 12: the Sixty scene-move cases and the offer cases unchanged within noise ("yes" to the walk offer 12 of 12 with Tom; to "want me to come?" 10 of 12).

Out of earshot: a character in the scene's place can be `apart`: visible, but too far off to hear a conversation at a normal volume. `WorldState.present_ids` is who is in the place, `hearing_ids` who is in the conversation (here and not apart); only the latter can speak (`Chatter.candidates`), and what is said is stamped for them alone (`public`/`audience` in `turn`), so an apart character never sees the lines, forms no memory of them and is told nothing of them (privacy by construction, as with whispers). Scene text lists them apart ("In this place but out of earshot"); who comes and goes (`_note_leavers`, `_note_arrivals`, scene moves) still uses the place. Authored on the cast card and per preset cast entry (`apart`; `apply_preset` sets it for everyone the preset mentions) and kept up to date by the watcher (`apart` in `GUIDANCE`, 'true'/'false'); a scene move or an arrival brings everyone back into one conversation. Someone apart can join only by coming over: the director is shown them (`OUT OF EARSHOT` in its prompt) and may pick ONE as a speaker (`director.decide` keeps the first), or the player calls to them by name (`_addressed` includes them), and the engine then writes a one-line stage direction before they speak (`Chatter._approach`: a call to the state model, so it needs no narrator; plain "(X comes over to Sam.)" if that fails; stored as `kind="approach"` with the person's id, in `NOTICE_KINDS` and `memory._NOTICE`, and returned among the turn's `replies` as a narrator entry), adds them to the lines of this turn so far (what drew them) and sets `apart` false. A watcher change that brings someone within earshot with nobody saying so gets the same line at the end of the turn, so nobody joins unannounced. With nobody in earshot and the narrator on, the narrator answers; with it off, nobody replies. On Marlbeck market day (Sam wandering, Arthur and Kez across the square; `tests/experiments/exp_earshot.py`, DeepSeek, N=8, four whole turns): with everyone in earshot, as before, Kez spoke in 8 of 8 runs (19 replies over 32 turns, first in 5 of 8 openings) and nothing said anyone had come over; with the flag she spoke in 0, 4 and 3 of 8 runs over three runs of the experiment (0, 10 and 6 replies) and, in the last, no first words by Arthur or Kez came without a line saying they came over (0 of 8 each). Noisy: the director brought someone over to a Sam who had only wandered in turn 1 in 3, 6 and 1 of 8 runs, and with the narrator off a turn nobody answers shows "(no one replies)" (5, 2 and 7 of 8 openings over the three runs). Watcher (`exp_apart_watcher.py`, N=8): no change during a chat with Arthur, small talk or Kez calling across the square (0 of 8 each), Kez brought within earshot when Sam walks over to her 8 of 8 (Arthur sent out of it 3 of 8), Arthur sent out of it when he wanders off 7 of 8. Not measured live: bids mode (the director's choice of who comes over is kept there, covered only by a unit test), and a narrator-on scene.

Narration (needs the narrator on, which is how an author turns it on; Marlbeck ships with it on): the narrator speaks in four cases. (1) When the player comes to a place, before anyone there answers (`Chatter._arrival_cue`; a premove puts a forced narrator speaker first in the turn, with no memory lookup of its own; a move found by the watcher or announced by a character gets the beat after the marker, in the turn's `arrival`; the UI's move button passes `models` to `Chatter.move`, which returns `narration`). A failed call is logged and skipped, never a failed turn. The author's preset `opening` already sets that scene, and `begin_scene` adds nothing. (2) When nobody answers: in `_direct`, after the 'someone should answer a question' fallback, an empty speaker list with the narrator on becomes one narrator turn that says what comes of the player's line or action. (3) When the director lists it: `director.decide` gets a rule (`narrator_rule`, with `narrator_gap`, the lines since the narrator last described something) saying a narrator turn is for what no character can do: the result of something the player examines or tries, something happening around them that nobody speaks for, a moment that needs marking; first when the result must be known before anyone reacts, last when it marks the moment after; never to sum up what was said; usually not two exchanges running. These are soft limits in the prompt, not hard guards, because the author did not want a fixed cooldown. Switches: `CHATTER_NARRATE_ARRIVAL`, `CHATTER_NARRATE_EMPTY`, `CHATTER_NARRATE_DIRECTED` (0 turns each off). **Narrator lines are established fact, not stage-direction decoration**: memory formation gives a narrator line source `scene` (the strongest source below the author's confirmation), so whatever the narrator invents (a woman at the cheese stall, three men at the window tables) can be recorded as true for everyone who was there, and later narration or characters are held to it. Measured so far (DeepSeek, `tests/experiments/exp_narration.py`, Marlbeck, N=8 per case): arrival, the narrator spoke first in 24 of 24 runs over three runs of the experiment and a character answered after it in 18 of 24 (the rest were the empty Wheatsheaf, where the landlord carried on polishing glasses); a wander round the market with nobody near, the narrator spoke in 16 of 16 runs (once after a character had come over); a Sonnet judge found, of the beats it returned (arrival 5, empty 4; the other half of the judge calls failed on credit), one that added a small action for Sam, two that introduced unnamed extras who matter to the beat, and three flags about the slow clock that were the judge's arithmetic, not the narrator's. **Not measured: the director rule.** The OpenRouter balance ran out, so whole turns failed with 402 (calls asking for many output tokens fail first; `LEAN=1` skips formation and the watcher to spend less), and only a handful of examine turns completed (the narrator spoke in 4 of 4 with the rule on, 2 of 4 and 1 of 2 with it off; too few to say anything) and no ordinary-talk turns at all. So whether it over-narrates small talk, which is the main risk, is unknown: rerun `ONLY=talk,examine,drama` with and without `CHATTER_NARRATE_DIRECTED=0` before trusting the rule.

Redo notes (`Chatter.author_note`) are corrections to a thrown-away attempt, not facts of the scene. Told as "the truth of the matter", a complaint about the discarded draft ("Yasmin assigned three people to a two bed room") became story: other characters remarked on an assignment nobody in the kept conversation had made, and then each other's remarks. The note now says it is about the writing, that nothing in the earlier attempt happened, and that what it describes is not to be mentioned, reacted to or corrected. `tests/experiments/exp_redo_note.py` (fixture `fixtures/redo_note_history.json`, DeepSeek, 12 redos each): redos with a reply that mentions the mistake 11 of 12 before, 0 of 12 now (0 of 12 with no note); a direction note ("Ottoline answers yes...") is followed 12 of 12 under both wordings.

Place pull: a place the speaker knows, named in the last four lines they saw (the whole name, "Rose Room"), brings its authored description with it, up to two (`memory.place_picks`, no model call, after the model's own picks and before the lexical ones; `CHATTER_RECALL_PLACES=0` turns it off; only the prefetch passes `near`). Without it Margo, who had claimed the Rose Room, had its description in front of her in 3 to 6 of 20 replays and described it from nothing. On a snapshot of that session (`tests/experiments/exp_place_pull.py`, fixtures `place_pull_*.json`, DeepSeek): the Rose Room came back 3 of 12 times before and 12 of 12 after, Margo's reply used a real detail of the room (mirror, dressing table, en-suite, cream, two beds) 7 of 20 times before and 12 of 20 after, and the cost was 0.6 more memories per line (2.7 to 3.3). **Not shown:** that it cuts contradictions. A Sonnet judge found 0 of 20 replies contradicting the description without it and 2 of 50 with it (noise), and invented decor (a fireplace, wallpaper) turned up in over half the replies either way, since the "balanced" invention dial invites sensory detail. It also does not help a room nobody names: Delphine's invented "west double" never named the Gold Room she must have meant, which came back in 4 to 5 of 12 runs either way.

How people look: every character and the player has a lasting `description` (age, build, manner: what anyone who sees them can tell) and a transient `appearance` (clothes, injuries, dirt, paint: how they look right now), and the player also has a private `background` that no prompt ever sees. `WorldState._looks_lines`, in `render_scene`, shows each viewer how everyone present looks (the player always; a character only while in the scene; the viewer's own line begins "You"), worded as all they know of them by sight, so the rest is learned from what is said or done. The watcher keeps `appearance` up to date (field `appearance` in `GUIDANCE`; target `player` for the player's, which takes that field only); `status` is for what they are doing and their mood. It is authored in the Cast tab (character cards and the player section, in the live game and the scenario editor), and `scenario.build_world` takes `description`, `appearance`, `player_description` and `player_appearance`, though the AI drafter writes none of them. Presets do not carry appearance (`PRESET_CHAR_FIELDS` is unchanged), so a preset leaves everyone as they are dressed; per-character knowledge of the player's past still goes through seeds with subject `player`. Measured on Marlbeck (DeepSeek): asked "can you tell where I'm from?" (`exp_player_desc.py`, 8 runs), Arthur and Kez said London in 13 of 15 replies with a description that says Londoner and 2 of 15 without (before it moved from the fixed prompt into the scene text: 14 of 15 and 1 of 16). The watcher (`exp_appearance.py`, 8 to 12 runs per case): a spill down the player's shirt recorded 7 of 8, a character's mud and torn sleeve 8 of 8, 6 of 8 and 9 of 12 over three runs (the rest recorded nothing), the player taking a jacket off 8 of 8, a plaster on two fingers only 3 of 12 (the watcher usually returns nothing for a small mark; not tuned further, since looser wording would raise false records); none recorded for mood (0 of 8) or small talk (0 of 8). Saying "I'll nip home and change" recorded a change that had not happened in 3 of 8 runs until the guidance gave that sentence as an example (1 of 12 after). Before the guidance said "no pronouns" the watcher wrote "his shirt" for a player described as "they". A first probe of the description ("what gave it away?") did not separate the cases, because the scenario text already gave the address and the van.

Embedding shortlist (`vectors.py`): for a character who knows more than 1,000 memories (`CHATTER_RECALL_EMBED_MIN`), `memory.retrieve` shows the model only the 30 memories nearest the line plus the 30 nearest its rewrite as a standalone question (`CHATTER_RECALL_EMBED_K`), instead of an index of all of them. Memory text is embedded once through OpenRouter (`CHATTER_EMBED_MODEL`, default `qwen/qwen3-embedding-8b`; needs numpy) and kept in `memories.vectors.npz` beside the store, keyed by a hash of the text; if embeddings fail the model reads every memory as before. `CHATTER_RECALL_EMBED=0` turns it off. **It is a safeguard for stores too big to read whole, not an accuracy gain**: in `tests/experiments/exp_embed_*.py` (model-written probes and distractors on the Sixty session, 24 oblique and 24 conversation-dependent lines, noise about +-3), the embeddings alone found the right memory well in small pools (94% in the top 3 of 41) and degraded with size (about 60% at 2,000; model pick alone about the same or worse), and the shortlist plus model pick was level with reading the whole index at 2,035 memories (oblique 9.0 vs 8.5 of 24, dependent 13.0 vs 16.2) while taking 6.2 s a call against 2.6 s. Shortened vectors (`CHATTER_EMBED_DIMS`) cost accuracy.

The UI is three pages: `loader.html` at `/` (sessions, scenarios, create), `index.html` at `/play` (the game), `editor.html` at `/editor/<id>` (edit a saved scenario). The authoring editors (cast, places, presets, reserved topics, schedule, knowledge, world prompt) are one shared set: markup in `templates/_*.html` partials, code in `static/editors.js`, pointed at the live world or a scenario by `EDIT` (play-only features are gated on `EDIT.live`). Other shared files: `static/common.js`, `static/app.css`. The UI tests read all of these together (`ui_text()` in `test_engine.py`).

## Design principles (keep)

- **Privacy is structural, not prompted.** A model that never sees a secret can't leak it: formation runs per audience group over only the lines that group witnessed, hidden facts never enter character or director prompts, discovery is a separate call.
- Memories, discoveries and unlocks must quote exact words from the exchange and the quote is verified. Place, time and provenance are stamped from the evidence line, never chosen by the model.
- Both failure directions matter: leaks and under-sharing.
- Authored world fields are never touched by the watcher; mutable state stays as short plain strings so hand-editing stays easy.
- Prompt changes get measured (counts over N runs, state sample sizes and caveats, retract claims when data contradicts them).

## Working with the user

- Short steps: build the feature, test it live against a real model, report honestly including what didn't work.
- For genuinely semantic design forks (behaviour or privacy), ask 1 to 3 focused questions before building. Don't ask about things with a conventional default.
- Their working model is `deepseek/deepseek-v4.1-flash` via OpenRouter, reasoning off for background steps. The UI fields still default to Claude; test drivers pass DeepSeek explicitly.
- Their session data (`world.json`, `memories.json`, `conversation.json`) is disposable. Run tests in the live app and leave results there; no backup/restore. `/api/reset` is fine. Use temp dirs for the deterministic suite and repeated experiments.
- Give a short status line during long work and a clear final summary.

## Gotchas

- Bash tool: large heredocs fail and backslashes get collapsed. Write patch scripts with the Write tool and run them, or use Edit; assert exact anchors so patches fail loudly.
- `window.confirm()` is auto-dismissed in the embedded browser pane; destructive buttons use a two-click arm pattern.
- A hung turn is usually the model; check `preview_logs`.
- `memory.form`'s prompt has many deliberate paragraphs (SUBJECT, EVIDENCE, TIME, DETAIL, claims, STANCE, and the exchange-by-move sentence); change them only with measurement. Tried and not kept: a second "does the conversation say this?" call using the working model (it dropped or mangled good notes: 9.0 of 14 key facts recorded against 12.0, and the share of partly-supported notes did not fall), an "assignments and decisions" paragraph (no better: 7 of 10 runs still recorded an acceptance nobody voiced, against about half without it), and a stricter stance definition (it cut stance notes from about 56 to about 4 over three runs, which would leave most "a position they may change" notes as "established, stay consistent"). `tests/experiments/exp_cases.py` (one exchange, N runs) and `exp_continuity.py` (the whole session, a stronger model judging) measure these. Recording exchanges move by move costs roughly one of twelve minor facts (the ham, the rota) and removes most invented acceptances.
